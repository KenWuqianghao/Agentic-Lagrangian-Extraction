New this week

Closing the loop with experiment

reverse asks whether the .fr matches the paper it came from. These ask the other question: whether the model is already excluded. A model can transcribe its source perfectly and still describe a region ruled out years earlier.

ads_interface.py

NASA ADS client

Reaches the published astrophysical and cosmological literature INSPIRE and arXiv searches miss, and searches paper bodies rather than just abstracts — which is where a numeric limit usually sits.

constraints.py

Model → limit queries

Maps field content onto the words experimenters use, so S1_LQ_RR reaches "leptoquark". Then reads bounds out of prose in the three forms limits are normally written, keeping the source sentence for every record.

limits_tools.py

Three agent tools

Search, find-limits, extract-constraints. Without an ADS token they degrade to returning the queries to run by hand rather than failing.

What testing against the real service changed

The mocked tests were confidently wrong

Every unit test passed while the tool returned the wrong papers. The first live query for a leptoquark model returned "B-physics anomalies: a guide to combined explanations" — a theory review, not a limit. Three separate bugs, none reachable without a real token.

BugWhy it happenedFix
wrong
discriminator		 abs:"ATLAS" matches phenomenology that merely mentions ATLAS. ADS indexes collaboration papers under "ATLAS Collaboration" as an author. Now returns "Search for a leptoquark in events with…"
ranking
inverted		 Sorted by citations — but a review of a model is cited far more than the experiment constraining it. Experimental searches sort newest first; a 2026 limit supersedes the 2015 one. Citations only tie-break.
bound
silently lost		 "masses between 1.5 and 3.0 TeV are excluded" matched the single-sided pattern on its upper number. Ranges are their own record kind carrying both edges, matched first so they cannot be double-counted.
query
timeout		 Full-text ADS searches scan paper bodies; a 30s ceiling with no retry dropped a whole query. 90s with one retry. That stage went from timing out at 50.8s to 6 papers in 23.4s.

A fifth bug surfaced the moment a real token existed: a token-precedence test asserted the environment variable wins, which only held on a machine with no configured token. It now neutralises the config leg explicitly.

Honest gaps

What does not work yet

Blocking

The LLM extract stage

Run against the local qwen2.5:14b on 24k chars of raw LaTeX, it returned a model named text-davinci-003, authors from a 1987 paper, and zero particles. The empty spec then correctly failed to compile.

This is a capability gap, not a tool bug — the chain propagated the failure exactly as it should. Needs a stronger model, or the relevant section fed in rather than the whole preamble.

Expected

Bounds are in bodies, not abstracts

The limit search returns the right papers, but extracting numbers from their abstracts yielded nothing: a 2026 abstract said limits were set "for masses between 1.5 and 3.0 TeV" without stating the bound. The extractor correctly reported none. The numbers live in the paper body — which is what ArxivSourceTool and PDFToTeXTool are for.
