# The September 2026 physicist findings, and what the reruns show

Ian and Konstantin reviewed the agent-generated FeynRules models and reported
five defects across four benchmark models. This document states what each one
was, what caused it, what changed, and what the reruns measured.

Generated tables live beside this file and are regenerated by script:

| file | what it holds |
|---|---|
| `single_model_papers.md` | which benchmark papers define exactly one model, and which reference files are mispaired |
| `ablation_report.md` | per-finding, per-run and per-variant results for every rerun arm |
| `rerun_score_<variant>.md` | field-content score against the FeynRules-DB reference |

## The findings

| # | model | finding | verdict | cause |
|---|---|---|---|---|
| 1 | Top-Philic Z' | missing kinetic and mass term for V1 | **not a defect** | the `.fr` has `LV1kin`; the *paper* omits it. A crosscheck row label read as a gap in the model. |
| 2 | 368 sextets | missing 1/Λ and 1/Λ² prefactors | **confirmed vs the paper** | the run had opened its own reference file, which absorbs κ/Λⁿ into dimensionful coefficients, and copied that convention |
| 3 | EffLRSM | reconstruction omits the charge conjugation on the light neutrino | **confirmed** | ν^c written as a bare field; lepton-number conserving where the paper violates it by two units |
| 4 | General U(1) | missing SU(2) ε contraction in the neutrino Dirac Yukawa; Higgs U(1)_X charge sign flipped | **both confirmed** | `LLbar[ii] … Phibar[ii]` on a shared index is not an SU(2) singlet; the charge was copied from Table I, whose hypercharge convention differs from the Yukawa equation's |
| 5 | EffLRSM | Z_R normalisation multiplies by `Sqrt[1 − tan²θ_W/κ²]` where Eq. (8) divides | **confirmed** | see below |

### Finding 5 is a tooling defect, not a physics mistake

The paper's LaTeX reads

```latex
\mathcal{L}_{\ZR-f-f} = \frac{-\kappa_{R}^f g}{\sqrt{1 - (1/\kappa_{R}^f)^2 \tan^2\theta_W}} ...
```

The PDF-to-text extraction the benchmark fed the agent flattens that fraction
into separate lines, so numerator, bar and denominator become indistinguishable
from a product. Two independent readers made the same slip: the extraction
agent while writing the model, and the crosscheck agent while transcribing the
paper — which is why the crosscheck graded the row "agree". At κ = 1 and
s_w² = 0.2312 the coupling is 30% low, so every Z_R rate is low by 0.49.

The fix is at the source, not in the prompt: every benchmark paper now has its
**LaTeX e-print** cached beside the PDF text, and the harness takes
`--paper-source tex`. One earlier rerun (v2/s1) had already recovered the right
placement by cross-checking the paper's own partial-width formula, which is now
rule 7 of the prompt for the cases where no LaTeX exists.

## What changed

**Paper source.** All 28 papers now have `text/<id>_source.tex` fetched with
`ArxivSourceTool` (manifest `latex_sources.json`). Fractions, roots and
sub/superscripts survive intact.

**Prompt.** `prompt_addendum_v3.txt` keeps the v2 physics rules and adds:
fraction and root placement (read the LaTeX literally; otherwise cross-check a
width or cross-section that depends on the same coefficient); mass mixing; and
the FeynRules/UFO construct rules that every earlier compile failure traced to
— `AddGaugeRepresentation` for non-fundamental colour representations, no
Mathematica-protected or SM.fr names, class indices ≥ 100, `InteractionOrder`
on every coupling, explicit tensor component values, matrix-form flavour
couplings, exactly one declared total, no field-free terms.

**Measurement.** `rerun_predicates.py` gained two deterministic checks written
against the construct rather than symbol names:

- `efflrsm_zr_normalisation` — the Z_R root must sit in a denominator. It
  passes the FeynRules-DB reference and fails the reviewed file, which is the
  minimum a finding-check must do. 21 unit tests in
  `test_rerun_predicates.py` cover the placement forms (explicit `/`,
  parenthesised group, negative power) and the near-misses.
- `sextets_gauge_representation` — a field carrying a 6, 8, 10 or 15-valued
  colour index needs `AddGaugeRepresentation[SU3C -> {T, index}]`, or it does
  not couple to gluons. Every earlier sextet rerun fails this; the reference
  passes it. This finding came from our own readers, not from Ian.

Two bugs in those checks were caught by running them against files the
framework did *not* render, and both would have understated the no-tools arm:

- The checks read the `.fr` with regexes tuned to the renderer's layout, so a
  hand-written class block with aligned arrows did not match and a correct
  model was marked wrong. They now parse the file with the repo's own
  balanced-brace `.fr` parser, which is indifferent to whitespace.
- One correct model wrote the Z_R denominator as a named parameter
  (`nZRq == { Value -> Sqrt[1 - tw2/kapRq^2] }`) and then divided by that
  name. Reading the root's own syntactic position called that a multiplication.
  The check now follows one level of indirection.

Both are covered by tests, because a measurement instrument that flatters or
penalises one arm is worse than no measurement.

A fourth bug was in the chain harness rather than the checks. Its cleanup step
killed Wolfram kernels by name, so two compiles running at once killed each
other and the survivor reported a compile failure that never happened — some
"failures" came back in two or three seconds, which is less than FeynRules
takes to load. Cleanup is now scoped to the compile's own process group, and
every failing row was re-verified with nothing else on the machine. Rows that
passed were never at risk: a killed kernel cannot produce a passing compile.

**Only papers that define one model.** Ian asked that the eval run only where
the paper cannot be confused for a different model. Each of the 28 papers was
classified by one reader and two adversarial refuters (a physics-content lens
and a reference-file lens), and a paper is selected only when every vote cast
agrees. 18 of 28 qualify. The exclusions are not noise:

- `Sextets` and `Triplets` are **the same paper** (arXiv:0909.2666) paired with
  different references; the paper explicitly offers antitriplet *or* sextet as
  a choice the implementer must make.
- `HiggsCharacterisation` offers spin-0, spin-1 and spin-2 alternatives;
  `DMsimp` spin-0 vs spin-1 mediators; `HNLs` Majorana vs Dirac; `VLQ` a
  singlet t' vs a fourth generation; `MSSMD` two different benchmarks.

The classification also found **five reference pairings that cannot be scored
at all**, which matters because a field-F1 against them measures nothing:

| model | problem |
|---|---|
| `LeptoQuark` | the scored reference is a vector-like-fermion add-on the paper never defines; the paper's U(1)+Z'+G' model is in three other files |
| `CHEIDI` | the benchmark text is arXiv:1010.3251**v2**, a FeynRules–WHIZARD interface paper with no model; the reference implements the withdrawn v1 physics |
| `VLC_LN` | the reference implements only a collider subset of the paper's composite model |
| `topBSM` | already corrected once; the current reference has no new fields |
| `MSSMD` | the listed publication is a CMS search, not the paper defining the Lagrangian |

16 of the 18 single-model papers are both single-model and scorable.

## The rerun arms

Same models, same seeds, same physics rules; one variable at a time.

| arm | agent tools | paper source | what it isolates |
|---|---|---|---|
| `v3_tools` | file reading + the schema and renderer | LaTeX | the framework as shipped |
| `v3_notools` | **none** — paper and SM.fr inlined in the prompt, agent writes the whole `.fr` itself | LaTeX | what the toolkit is worth: the ablation Ian asked for |
| `v3txt_tools` | file reading + schema and renderer | PDF text | how much of the gain is the LaTeX source alone |

Baselines `v1` (original prompt) and `v2` (physics addendum), both on PDF text,
are carried in the same tables.

Every arm runs sandboxed: the agent sees the paper, `frmodel.py`, `render.py`
and `SM.fr`, and nothing else. This matters because an audit of the *original*
fleet found 18 of 28 runs had opened their own reference file mid-run. Each run
records whether the paper was read and whether anything outside the sandbox was
touched.

## Results

Every number below is generated into `ablation_report.md`; nothing here is
typed by hand. Two seeds per model per arm.

**The findings.** Five of the six checks pass in every v3 seed, in both the
tools arm and the no-tools arm:

| finding | v1 | v2 | v3 PDF text | v3 LaTeX | v3 LaTeX, no tools |
|---|---|---|---|---|---|
| Z' kinetic + mass term | 2/2 | 2/2 | 2/2 | 2/2 | 2/2 |
| sextet explicit 1/Λⁿ cutoffs | 2/2 | 2/2 | 2/2 | 2/2 | 2/2 |
| sextet `AddGaugeRepresentation` | 0/2 | 0/2 | **2/2** | **2/2** | **2/2** |
| EffLRSM ν^c on the W_R current | 2/2 | 2/2 | 2/2 | 2/2 | 2/2 |
| EffLRSM Z_R root in the denominator | 1/2 | 2/2 | 1/2 | **2/2** | **2/2** |
| General U(1) ε contraction + Higgs charge | 1/2 | 2/2 | 0/2 | 1/2 | 1/2 |

**The third column is the point.** It runs the *same* v3 rules on the *old*
PDF-extracted text, so the only thing that differs from the fourth column is
what the agent read. The two remaining findings separate cleanly:

- The sextet gauge representation is fixed by the **prompt**: 2/2 in all three
  v3 arms, whatever the paper source, and 0/2 in every arm before them.
- The Z_R normalisation is fixed by the **paper source**: 1/2 on PDF text and
  2/2 on the LaTeX, with the rules held constant. That is the hypothesis
  stated at the top of this document, measured rather than argued.

**The one that did not,** and it fails two different ways — both new disguises
of the defect Ian reported.

- One seed writes the Dirac neutrino Yukawa after electroweak symmetry
  breaking, `H vlbar.ynu.ProjP.NR`, instead of the doublet form
  `LLbar[..,i,..] Phibar[j] Eps[i,j]`. With no doublet there is no ε
  contraction to get right, and the charged-lepton partner of the vertex is
  silently dropped.
- Another derives the Higgs U(1)_X charge correctly — its header comment says
  "invariance of the three SM.fr Yukawas fixes X(Phi) = +xH/2" — and then never
  declares it or uses it. The reasoning is right and the model does not carry
  it, so the Z' does not couple to the Higgs at all.

Two rules follow, and neither is in the addendum yet: write Yukawas in the
symmetric phase with the doublet, never with the physical Higgs; and every
charge you derive must appear in the model, not only in a comment.

**The sextets are still the hard case.** `AddGaugeRepresentation` is present
now, so the sextets do couple to gluons, and both sextet checks pass in every
v3 seed. The chain is another matter: three of the four seeds run 15 minutes
without finishing. The fourth is the informative one — it compiles in 8.6
minutes, MadGraph imports the UFO, and it fails the **Hermiticity** check while
the kinetic-term and mass-spectrum checks pass. So the model does get through,
and what is left is a real non-Hermitian term rather than a stall. Adding the
gauge representation was necessary and not sufficient. The colour-sextet
algebra is expensive whichever way the `.fr` was written, and the remaining
defect is one for a physicist to read, not a harness problem.

**What the ablation says, including the part that does not flatter us.**

| arm | every finding resolved | full chain | field F1 |
|---|---|---|---|
| v1 — PDF text, original prompt | 4/8 | 2/8 | 0.90 |
| v2 — PDF text, physics rules | 6/8 | 3/8 | 0.88 |
| v3 — PDF text, v3 rules | 5/8 | not run | 0.84 |
| v3 — LaTeX, v3 rules, framework | 7/8 | 5/8 | 0.83 |
| v3 — LaTeX, v3 rules, **no tools** | 7/8 | **6/8** | 0.86 |

The reruns are a clear improvement on where we started: runs with every check
passing go from 4/8 to 7/8, and full-chain passes from 2/8 to 5–6/8.

But the gain does not come from the toolkit. Taking every tool away — no
schema, no renderer, the agent writing the `.fr` by hand from the paper and
`SM.fr` pasted into its prompt — matched the framework on the findings and
came out marginally *ahead* on the chain, 6/8 against 5/8, and on field
content, 0.86 against 0.83. On these four models the improvement is
attributable to the paper source and the prompt rules, both of which the
no-tools arm also had.

That is a small sample and one seed swings any of these numbers, so it is not
evidence the schema and renderer are worthless — the same rules produced the
same physics either way, which is itself a reason to trust the rules. It is
evidence that the *next* thing worth measuring is not the prompt. The
framework's one clear loss is instructive: the single tools-arm run MadGraph
rejected compiled cleanly and passed all three FeynRules checks, and its UFO
carries LaTeX-typeset parameter names (`name = '\\theta _c'`) that are not
valid Python — a renderer-side serialization leak of exactly the class the
repair-loop analysis catalogued. The hand-written files had no such failure.

**Not run:** the PDF-text arm was scored on the findings and the reference
but not put through the compile chain. Its purpose was to isolate the paper
source, which the findings column already does; the chain would have cost
another hour of Wolfram time without changing that comparison.

## Reproducing

```bash
# with a logged-in `claude` CLI
PAGES=single SEEDS=2 eval/benchmark_runs/run_ablation.sh

# scoring and reporting only, from existing agent output
python eval/benchmark_runs/ablation_report.py \
    --variants v1,v2,v3_tools,v3_notools,v3txt_tools \
    --pages Top-Philic-Zprime,368sextets,EffLRSM,GeneralU1 --seeds 2
python -m pytest eval/benchmark_runs/test_rerun_predicates.py -q
```
