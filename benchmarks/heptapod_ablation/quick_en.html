1. The two groups and the score

Tools group: Claude Code + the heptapod validation tools + our protocol and stop gate + a shell.
Vanilla: the same Claude Code with a shell only. It runs Mathematica and MadGraph itself.
Task: read a new-physics paper and write a FeynRules model, model.fr.
Score: if the model passes the 6-step check chain, the score is the F1 of the new-physics vertex kinds against the reference model (0 to 1). If the check chain fails, the score is 0. Section 2 explains this in detail.
Conditions: the same for both groups. 4-hour time limit; on each machine, 2 Wolfram kernels and 2 agents.

2. How the score is computed

For a reader who does not know this project. Short version: a pass/fail gate (like "it builds and the tests pass"), then a set comparison against an answer key.

model.frThe file that the agent writes
6 checks (gate)One failure → score 0
UFOParticle list + vertex list
Vertex kindsEach vertex reduced to what its particles are
F1 against the referenceScore from 0 to 1

  1. What the agent delivers

    A physics paper defines a model by its Lagrangian: one formula that gives all the particles and how they interact. The agent writes this Lagrangian as a FeynRules file, model.fr. FeynRules is a Mathematica package. It turns a Lagrangian into Feynman rules and exports them as a UFO (Universal FeynRules Output). A UFO is a set of Python files: particles.py lists the particles, and vertices.py lists the vertices. A vertex is a set of particles that can meet at one point of a Feynman diagram, for example "W′⁺ → e⁺ ν". Event generators such as MadGraph read the UFO to simulate collisions.

  2. The gate: 6 checks, all must pass

    1. CompileFeynRules loads the model with no error. 2. HermiticityThe Lagrangian equals its Hermitian conjugate (L = L†). If not, probabilities are not conserved. 3. Kinetic termsNo two fields mix in their kinetic terms. 4. Mass termsNo two fields mix in their mass terms: each field that the model declares as a physical particle really has a definite mass. 5. Mass spectrumFor each particle, the mass that the model declares agrees with the mass that comes from the Lagrangian, within 0.1%. 6. MadGraph importMadGraph 5 loads the UFO with no error.
    If one check fails, the score is 0. A physicist cannot use a model that is "almost right" but does not run. The same scorer checks both groups. The agent's own claims are not used.

  3. Reduce each vertex to a "kind"

    The agent and the reference use different names ("Wp" or "Wprime"). So the score compares what the particles are, not their names:
    • A Standard Model particle becomes its PDG code (the standard particle ID number), with the generation removed. Electron, muon and tau all become sm:cl (charged lepton). Up, charm and top all become sm:uq.
    • A new particle becomes (spin, electric charge, colour). The W′⁺ becomes bsm:spin3,q=1,col=1. Here "spin3" is the UFO convention 2s+1, so s = 1, a vector boson. col=1 means no colour charge.
    • Ghosts and Goldstone bosons are removed. They come from the gauge choice and are not physical particles.
    • Only vertices with at least one new particle are kept. Every model loads the same Standard Model, so the SM vertices give no information.
    The order inside a vertex does not matter, and identical kinds count once. The result is a set of vertex kinds for each model.

  4. Compare the two sets with F1

    The reference (the answer key) is the model of the same paper in the public FeynRules model database, compiled to a UFO in the same way.
    precision = matched ÷ kinds in the agent's model
    recall    = matched ÷ kinds in the reference
    F1        = 2 · precision · recall ÷ (precision + recall)
    Example: Wprime (a real run, tools group, Sonnet 5, seed 1). ℓ = any charged lepton, d and u = any down-type and up-type quark (the generation is removed). Green = in both. Yellow = only in the agent's model.
    W′⁺ · ℓ · νW′⁻ · ℓ · νW′⁺ · d · uW′⁻ · d · u W′⁺ · N · ℓW′⁻ · N · ℓ
    precision = 4 ÷ 6 = 0.67   recall = 4 ÷ 4 = 1.00   F1 = 0.80
    The paper has a right-handed neutrino N, and the agent put it in. The reference leaves N out. So on this paper, a model that follows the paper exactly gets 0.80, not 1.

  5. Average

    One run gives one score per paper. The tables in section 3 give the mean over the 13 papers that have a usable reference (3 of the 16 papers do not), then the mean over seeds.
What the score does not measure. It checks the structure of the model: which particles exist and which ones interact. It does not compare coupling values, signs, or the Lorentz structure of a vertex. It does not count copies: three heavy neutrinos with the same spin, charge and colour are one kind. A model with the correct vertices and a wrong coupling constant gets full marks.
Why this design. The gate gives 0 to a model that keeps the physics but does not run. Recall gives a low score to a model that passes the checks because it left the physics out. An earlier harness had such "empty passes": a new particle with no vertex at all.
Fixes to the answer key. We found 3 label errors in the references: Monotops (colour of two scalars), B-L-SM (the Higgs has a non-standard PDG code), and 331 (a free parameter β; we try the 4 values that the paper uses and keep the best). We changed only the reference labels. The same fix applies to every group.

5. Why the tools help

The stop gate catches "I think it passed"Vanilla sometimes writes "all checks pass" in its summary, but the scorer's checks fail. In the tools group, if the agent tries to stop and the last validation did not pass, the stop gate tells it to continue (up to 3 times).
More stableOn the same paper, vanilla sometimes gets full marks and sometimes 0. The tools group gets 0 much less often: the check chain passes in 82 / 91 runs against 68 / 91.
CheaperVanilla finds errors by trial and reads long logs. The tools give a short report and the next step. On each model, vanilla costs 2.7 to 3.8 times more.

6. Limits: what is not yet reliable

  • Largest weaknessThere is no held-out test. We changed the tools and the protocol after we read the failures on these 13 papers. We did not test if the result holds on new papers.
  • Haiku alone is not significantHaiku 5.5: +0.09, p = 0.16. Seed 2 goes the other way (0.57 against 0.69). The 5 failures of the Haiku tools group have one pattern: after the stop gate gave 3 "continue" messages, the agent stopped. At that time the validation had not passed, and validation calls were still available. Not confirmed that this is the main cause (see next step 2).
  • Sonnet 5.5 has 1 seed only+0.20, p = 0.09. The direction is the same as on the other two models. Alone, it is not significant.
  • The metric counts vertex kinds onlyIt does not compare coupling values or signs.
  • pSPSS and 331With the three models together, pSPSS is the only paper where vanilla is higher (−0.06). It is also the paper with the most noise. On 331, vanilla is higher in all three Sonnet 5 runs; on Sonnet 5.5 the result is the opposite. 331 needs a standalone model. The current add-on format cannot give the full model.
  • Run problem, fixedOn the Mac, two hung Wolfram kernels held both kernel slots. We discarded the 11 runs that this affected and ran them again. Haiku vanilla s1 Monotops possibly had the same problem. Without that run, the Haiku difference is +0.08.
  • Retry rule, same for both groupsOn Sonnet 5.5, ALRM_general and MDMmodel hit the 4-hour limit in both groups on the first attempt. Both groups got one more attempt. We use the second result.

7. Next steps (your decision)

  1. Held-out test (recommended): choose 5 to 8 new papers and run each group 1 to 2 times. Result: this removes the largest weakness. Cost: 1 to 2 days to choose the papers and build the reference models; about $150 to $300 for the runs on Sonnet 5. Sonnet 5.5 or Haiku costs much less.
  2. Give weaker models more "continue" messages: change the stop gate limit from 3 to 6 and run the Haiku tools group again. Result: this shows if the 5 Haiku failures come from this limit. Cost: about $15 (2 seeds).
  3. Write the report: the current data is sufficient for a conclusion with its limits stated. No cost.
