1. 先认识两组和分数

工具组：Claude Code + heptapod 的验证工具 + 我们的协议和结束门 + 命令行。
vanilla：同一个 Claude Code，只有命令行。它自己运行 Mathematica 和 MadGraph。
任务：读一篇新物理论文，写出 FeynRules 模型 model.fr。
分数：模型通过 6 步检查链时，分数 = 新物理顶点种类和参考模型的 F1（0 到 1）。检查链不通过时，分数 = 0。
条件：两组相同。4 小时时限，每台机器 2 个 Wolfram 内核和 2 个 agent。

4. 为什么工具有用

结束门挡住「以为通过」vanilla 有时在总结里写「全部通过」，但是评分器的检查失败了。工具组的 agent 想结束而验证没有通过时，结束门要它继续（最多 3 次）。
更稳定vanilla 在同一篇论文上有时满分，有时 0 分。工具组的 0 分少很多：检查链通过 82 / 91 对 68 / 91。
更便宜vanilla 自己反复试错，读很长的日志。工具给出短的报告和下一步。所以每个模型上 vanilla 都花 2.7 到 3.8 倍的钱。
