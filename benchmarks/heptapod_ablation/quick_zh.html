1. 先认识两组和分数

工具组：Claude Code + heptapod 的验证工具 + 我们的协议和结束门 + 命令行。
vanilla：同一个 Claude Code，只有命令行。它自己运行 Mathematica 和 MadGraph。
任务：读一篇新物理论文，写出 FeynRules 模型 model.fr。
分数：模型通过 6 步检查链时，分数 = 新物理顶点种类和参考模型的 F1（0 到 1）。检查链不通过时，分数 = 0。第 2 节详细解释。
条件：两组相同。4 小时时限，每台机器 2 个 Wolfram 内核和 2 个 agent。

2. 分数怎么算

写给不了解这个项目的读者。简单说：先过一道「能不能用」的门（像「能编译、测试通过」），再和标准答案做集合比较。

model.fragent 写的文件
6 项检查（门）一项失败 → 0 分
UFO粒子表 + 顶点表
顶点种类每个顶点只看粒子「是什么」
和参考模型比 F10 到 1 的分数

  1. agent 交什么

    一篇物理论文用 拉格朗日量 定义一个模型：一个公式给出所有粒子和它们怎样相互作用。agent 把拉格朗日量写成 FeynRules 文件 model.fr。FeynRules 是一个 Mathematica 包。它从拉格朗日量算出费曼规则，然后导出 UFO（Universal FeynRules Output）。UFO 是一组 Python 文件：particles.py 列出粒子，vertices.py 列出 顶点。顶点是能在费曼图的一个点上相遇的一组粒子，例如「W′⁺ → e⁺ ν」。MadGraph 这样的事例产生器读 UFO 来模拟对撞。

  2. 门：6 项检查，全部要通过

    1. 编译FeynRules 加载模型，没有错误。 2. 厄米性拉格朗日量等于它的厄米共轭（L = L†）。否则概率不守恒。 3. 动能项动能项里没有两个场混合。 4. 质量项质量项里没有两个场混合：模型声明为物理粒子的场，真的有确定的质量。 5. 质量谱每个粒子声明的质量，和从拉格朗日量算出的质量一致，误差在 0.1% 以内。 6. MadGraph 导入MadGraph 5 加载 UFO，没有错误。
    有一项失败，分数就是 0。一个「差不多对」但是跑不起来的模型，物理学家用不了。两组用同一个评分器检查。agent 自己说「通过了」不算数。

  3. 把每个顶点变成一个「种类」

    agent 和参考模型给粒子起的名字不同（「Wp」或「Wprime」）。所以分数比较粒子 是什么，不比较名字：
    • 标准模型粒子 变成它的 PDG 编号（标准的粒子编号），去掉代数。电子、μ 子、τ 子都变成 sm:cl（带电轻子）。上、粲、顶夸克都变成 sm:uq。
    • 新粒子 变成（自旋，电荷，颜色）。W′⁺ 变成 bsm:spin3,q=1,col=1。「spin3」是 UFO 的写法 2s+1，所以 s = 1，是矢量玻色子。col=1 表示没有色荷。
    • 去掉鬼场和 Goldstone 玻色子。它们来自规范选择，不是物理粒子。
    • 只保留至少有一个新粒子的顶点。每个模型加载同一个标准模型，所以 SM 顶点不提供信息。
    顶点里粒子的顺序不重要，相同的种类只算一次。结果是每个模型的一个顶点种类 集合。

  4. 用 F1 比较两个集合

    参考模型（标准答案）是公开的 FeynRules 模型数据库里同一篇论文的模型，用同样的方法编译成 UFO。
    precision（精确率）= 匹配数 ÷ agent 模型的种类数
    recall（召回率）   = 匹配数 ÷ 参考模型的种类数
    F1                 = 2 · precision · recall ÷ (precision + recall)
    例子：Wprime（一次真实运行，工具组，Sonnet 5，seed 1）。ℓ = 任意带电轻子，d 和 u = 任意下型和上型夸克（代数已去掉）。绿色 = 两边都有。黄色 = 只有 agent 的模型有。
    W′⁺ · ℓ · νW′⁻ · ℓ · νW′⁺ · d · uW′⁻ · d · u W′⁺ · N · ℓW′⁻ · N · ℓ
    precision = 4 ÷ 6 = 0.67   recall = 4 ÷ 4 = 1.00   F1 = 0.80
    论文里有右手中微子 N，agent 把它写进去了。参考模型没有 N。所以在这篇论文上，完全照论文写的模型得 0.80，不是 1。

  5. 平均

    一次运行在每篇论文上得一个分数。第 3 节的表先对 13 篇有可用参考模型的论文求平均（16 篇里有 3 篇没有），再对 seed 求平均。
分数不衡量什么。它检查模型的 结构：有哪些粒子，哪些粒子相互作用。它不比较耦合常数的数值和符号，也不比较顶点的洛伦兹结构。它不数副本：自旋、电荷、颜色都相同的三个重中微子算一个种类。顶点都对、耦合常数错了的模型，也得满分。
为什么这样设计。门让「物理都在、但是跑不起来」的模型得 0。召回率让「为了通过检查而删掉物理」的模型得低分。以前的 harness 有这种「空通过」：新粒子一个顶点都没有，检查却通过了。
对标准答案的修正。我们在参考模型里发现 3 个标注错误：Monotops（两个标量的颜色）、B-L-SM（Higgs 用了非标准的 PDG 编号）、331（自由参数 β；我们试论文用的 4 个值，取最好的一个）。我们只改了参考模型的标注。修正对所有组都一样。

5. 为什么工具有用

结束门挡住「以为通过」vanilla 有时在总结里写「全部通过」，但是评分器的检查失败了。工具组的 agent 想结束而验证没有通过时，结束门要它继续（最多 3 次）。
更稳定vanilla 在同一篇论文上有时满分，有时 0 分。工具组的 0 分少很多：检查链通过 82 / 91 对 68 / 91。
更便宜vanilla 自己反复试错，读很长的日志。工具给出短的报告和下一步。所以每个模型上 vanilla 都花 2.7 到 3.8 倍的钱。

6. 限制：哪些地方还不可靠

  • 最大的弱点没有留出测试。工具和协议是看了这 13 篇的失败以后改的。在新论文上是否成立，没有测试。
  • Haiku 单独不显著Haiku 5.5：+0.09，p = 0.16。seed 2 是反向的（0.57 对 0.69）。Haiku 工具组的 5 次失败有同一个模式：结束门给出 3 次「继续」以后，agent 停了。那时验证没有通过，验证次数还有剩余。这是不是主要原因，没有确认（见下一步第 2 项）。
  • Sonnet 5.5 只有 1 个 seed+0.20，p = 0.09。方向和另外两个模型一样，单独不够显著。
  • 指标只看顶点种类不看耦合的数值和符号。
  • pSPSS 和 331合并以后，pSPSS 是唯一 vanilla 更高的论文（−0.06），也是噪声最大的一篇。331 在 Sonnet 5 上 vanilla 三次都更高，在 Sonnet 5.5 上反过来。331 需要独立模型，现在的 add-on 格式做不出完整模型。
  • 运行中的问题，已处理Mac 上两个卡住的 Wolfram 内核占了两个位置。受影响的 11 次运行作废并重跑。Haiku vanilla s1 的 Monotops 可能也受影响；去掉它以后 Haiku 的差是 +0.08。
