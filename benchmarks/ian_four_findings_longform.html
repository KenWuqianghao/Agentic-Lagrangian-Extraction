Ian's Four Findings

Ian and Konstantin read four agent-generated FeynRules models closely and reported one failure mode in each. This page traces every finding to its cause, shows what the reruns did about it, and reports the thing the tracing turned up on the way: most of the original benchmark runs had read the answer key. The last section lists the fix for every issue on the page, in one place, for the meeting.

01 · Verdicts

Where each finding stands

Each finding was re-derived from the files by one analyst and then attacked by two independent verifiers (one re-opening every quoted line, one checking the physics). All seven votes confirmed the analyses.

EffLRSM

“Reconstruction omits the charge conjugation on the light neutrino”

LWRLightNuNonHC := ... XL[ll,nn]
   bar[ve[nn]].Ga[mu].ProjP.l[ll] WR[mu]   (* line 192 *)

In the .fr, not only in the reconstruction. The bare field conserves lepton number; the paper's νc violates it by two units, as a Majorana ν requires. Inert at the benchmark point (X = 0) and absent from the reference, but wrong as written.

confirmed · both parts

General U(1)

“Missing SU(2) epsilon contraction in the neutrino Dirac Yukawa; Higgs U(1)X charge sign flipped”

LLbar[sp1,ii,ff1].ProjP.NR[sp2,ff2] Phibar[ii]   (* no Eps *)
qHX == { Value -> -xH/2 }                        (* Table I, literally *)
reference: Phibar[jj] Eps[ii,jj];  BL -> xH/2

A shared index on two anti-doublets is not a singlet; after SM.fr's Φ components it yields charge-violating l̄Nh and ν̄NG⁺ vertices, hidden because every yν was 0. The paper's Table I and Eq. (1) use different Y(H) conventions; +xH/2 is the unique choice making all five Yukawas invariant. Sharper than the tool's own crosscheck, which had marked the sign “agree”.

real vs paper · run contaminated

368 sextets

“Missing 1/Λ and 1/Λ² prefactors in higher-dimensional operators”

LFu := CFu[mm] I Sqrt[2] K6[..] T[..] K3bar[..]
       sFubar.(σ).CC[uR] FS[G,mu,nu,aa] + ...  (* no Λ *)

What this means for the numbers reported earlier. For those 18 models, the extraction scores and the “passed one-shot” provenance measured the agent's ability to copy a physicist's file, not to read a paper. The validation chain still says what it said — those files compile — but no pass rate from the original fleet should be quoted as an extraction result until the whole set is re-run sandboxed. Of Ian's four: Z′ and EffLRSM were clean, 368sextets read its own reference, General U(1) read others' but not its own.

The fix, now in the rerun harness. The agent runs in a temporary directory that mirrors the repo layout but holds only the paper text, the schema, the renderer and SM.fr — nothing else exists, and the directory's path reveals no repo location. Every run records whether the paper was read and whether any tool call reached outside the sandbox; reaching the same paper text through a real path is logged as benign, anything naming reference_cache taints the run.

What the compile adds to the reading. The four Z′ files and 368 sextets v2/s1 settle the two conventions the readers were unsure of: FS[] on a gauge-singlet vector and CC[] on a fermion both compile and import. Every other failure is one of four constructs: an explicit index on a field inside DC[] or a flavour matrix written with explicit indices instead of matrix form (FeynRules' UFO writer leaks its internals into vertices.py); a pattern-rule Definitions on a tensor parameter (exported verbatim as a parameter name); a new coupling with no InteractionOrder (MadGraph refuses order-1 couplings); and a nested index that stalls FeynRules. None is visible from the paper, and none is a physics error — they belong in the schema and the next addendum, not in a physicist's review.

04 · The prompt addendum

Six rules and a self-audit, appended to the extraction prompt

  • free fieldsA named kinetic + mass term for every new particle class, even when the paper shows only Lint, using the class Mass symbol and summed into the total.
  • cutoffsEvery operator of dimension d > 4 carries 1/Lam^(d−4) with Lam an External parameter at the paper's benchmark; dimensionless couplings stay dimensionless. Absorbing κ/Λⁿ is allowed only with the mass dimension and units stated.
  • conjugationWherever the paper writes ψc, write CC[psi] — never the bare field, even when the coefficient is zero at the benchmark.
  • SU(2)Two objects of the same conjugation type contract with Eps[ii,jj] on distinct indices; a doublet with an anti-doublet on a shared index. SM.fr conventions: Φ has Y = +½.
  • U(1) chargesNever copy a paper's charge table literally when its Yukawa equation uses a different convention; re-derive every SM field's new-U(1) charge from Yukawa invariance and say which sign was chosen and why.
  • self-auditBefore the JSON: one row per term with operator dimension, coupling dimension, Q / Y / new-U(1) sums (all zero), SU(2)/SU(3) contraction, CC[] where the paper has ψc, and the Hermitian partner.

What the residuals say about the next addendum. Four rules would have caught most of them: any non-fundamental colour representation needs an AddGaugeRepresentation line in raw_preamble; class indices start at 100 so they cannot collide with SM.fr; never use a Protected Mathematica symbol (N, C, D, E, I, K, O) as a class name; give a cutoff no InteractionOrder unless the paper's own implementation does; tensor parameters get an explicit value for every component, never a pattern-and-condition Definitions rule. The compile chain adds three: every new parameter carries an InteractionOrder; flavour matrices are written in matrix form (uqbar.VCKMR.Ga[mu].ProjP.dq), never with explicit generation indices; no explicit index on a field inside DC[]. Mixing diagonalisation is a modelling decision the prompt can ask about but not decide.

And what they do not say. The readers are language models reading the same files; agreement lowers but does not remove the chance of a shared mistake on FeynRules conventions. The compile chain, run after this review, settled the two they were unsure of (FS[] on a gauge-singlet vector and CC[] both compile), caught four defect classes none of them saw, and overturned one claim (the N file loads). That is why the compile step is not optional.

Read the drops carefully. Triplets, CHEIDI and ChernSimonsPortal fall from 1.00 to near 0 once their runs can no longer copy the reference; those are the honest baselines and each is a model to look at by hand. topBSM's drop turned out to be the benchmark's fault: its reference directory holds two files, and the entry had paired arXiv 1305.7386 — Zhang & Maltoni's t → qh EFT paper — with the heavy-resonance model instead of Krastanov's flavor-changing-Higgs model thu.fr, which declares no new particle at all. The sandboxed agent read the paper correctly and wrote the same Ouφ, OuG operators; the original run scored 1.00 by copying the wrong answer key. The pairing is corrected and the scorer now reports F1 as undefined, not zero, for references with no new fields. MSSMD's pairing is also suspect: its listed paper is a CMS search, which cannot define a 39-field Lagrangian. The two largest gains, pSPSS 0.22 → 1.00 and 331 0.20 → 0.41, are clean-run comparisons.

Through the compile chain. 11 of 28 pass FeynRules → UFO → MadGraph first shot, with no repair loop; 21 compile. The old fleet's 15 of 28 was measured on files that had, in 18 cases, copied a reference that compiles. The failures are the convention classes of §05 plus three new ones: a particle named W' (Wprime, CHEIDI — the prime is not valid Python), a field-free constant term exported as a vertex with no particles (EffLRSM, SMWeinberg), and a FeynRules recursion-limit crash (Monotops, SLQrules). Three models declare two total-Lagrangian symbols and the harness refuses to guess (DMsimp, VLQ, MSSMD); ALRM_general stalls in the Hermiticity check; Triplets compiles and imports but is not Hermitian.
