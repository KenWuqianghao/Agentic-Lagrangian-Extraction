**Summary of change:** In `model.fr`, the `nuR` unphysical-field `Definitions` rule (class `F[101]`) wrapped its dummy spinor index in `Module[{sp2}, ProjP[sp1,sp2] Nmaj[sp2,ff]]`. Wrapping a FeynRules dummy tensor/spinor index in `Module` gives it fresh-hygiene renaming on every rule application, which is not FeynRules' expected index-contraction idiom (dummy indices in a `RuleDelayed` substitution should be plain repeated symbols, as used everywhere else in this file, e.g. `mu`, `ii`, `sp`). This mismatch is the root cause of the reported UFO defect: when FeynRules expanded the Majorana Yukawa term `yM[ff1,ff2] anti[CC[nuR]][sp,ff1].nuR[sp,ff2] ChiBL` (the one Lagrangian term where `nuR` is contracted against its own charge conjugate, unlike the Dirac term where `nuR` pairs with the independent field `LLbar`), the unresolved `Module`-scoped substitution left an un-evaluated `ReplaceAll` expression in the internal parameter-naming step for the `yM` matrix element, which FeynRules then wrote verbatim into `UFO/parameters.py` as `yM1x2 /. yM = Parameter(...)` — not valid Python, which is exactly why `import particles` (and hence MadGraph's `import model`) failed with `SyntaxError: invalid syntax`. I removed the `Module` wrapper, leaving `Definitions -> {nuR[sp1_,ff_] :> ProjP[sp1,sp2] Nmaj[sp2,ff]}`, the standard FeynRules idiom for projecting a right-handed component out of a Majorana field, which preserves the field content, quantum numbers, and operator structure exactly while letting FeynRules treat `sp2` as an ordinary contracted dummy index.
