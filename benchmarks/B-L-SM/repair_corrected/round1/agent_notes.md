## Summary of changes to `model.fr`

I made four technical fixes, all preserving the physics content (fields, quantum numbers, operator structure, parameter values):

1. **Renamed the field `Chi` → `ChiBL`.** `Chi` is a protected Mathematica built-in (the hyperbolic-cosine-integral special function `Chi[z]`). Using it as a FeynRules `ClassName` shadows the built-in during Wolfram Engine evaluation, which plausibly explains the garbled internal errors in the validation log (`Part::pkspec1: Index[MR$Null]`, `Join::heads`, `StringJoin::string`) and the corrupted Hermiticity/kinetic/mass-diagonal check results. 2. **Renamed the field `N` → `Nmaj`.** `N` is a protected Mathematica built-in (numeric evaluation, `N[expr, prec]`), and the code called it as `N[sp2,ff]` — a two-argument pattern indistinguishable from `N`'s own built-in precision-argument syntax. This exactly matches the `builtin_symbol_collision` heuristic tag and is very likely the direct cause of the malformed UFO output (`lorentz.py` line 15's `1 = Lorentz(...)`, `vertices.py`'s stray `L.1`, and `parameters.py`'s `yM1x2 /. yM = Parameter(...)` syntax error) that broke MadGraph's Python import. 3. **Fixed the self-conjugate quantum-number inconsistency on `Nmaj`.** It was declared `SelfConjugate -> True` (Majorana) while also carrying `BL -> -1`. A field that is its own antiparticle cannot carry a nonzero charge under FeynRules' `QuantumNumbers` bookkeeping (charge would have to equal minus itself). Changed `BL -> -1` to `BL -> 0`, matching the task's explicit guidance on this exact defect class.

4. **Connected the reconstructed doublet quartic to the SM potential.** `lambda1BL` (the physically-correct, mixing-corrected Higgs quartic, `(MH^2 ca^2 + MH2^2 sa^2)/(2 vev^2)`) was defined but never referenced anywhere — confirmed directly in the generated `UFO/parameters.py`, where the auto-included SM parameter `lam` instead used the naive unmixed formula `MH**2/(2*vev**2)`. Added an `Internal` parameter override `lam == {Value -> lambda1BL, ...}`, which is the standard FeynRules technique for making a BSM extension file override an inherited SM parameter.
